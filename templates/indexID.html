apa itu Representasi *floating-point*?

Representasi *floating-point* adalah metode yang digunakan dalam komputasi untuk merepresentasikan bilangan riil secara aproksimatif. Metode ini memungkinkan cakupan nilai yang luas dengan adanya kompromi antara presisi dan rentang nilai. Berbeda dengan manusia yang memiliki pemahaman mendalam mengenai angka—terutama bilangan berbasis 10—komputer bekerja menggunakan sistem biner. Karena bilangan seperti 0,1, -2,5, dan sebagainya tidak dapat dikonversi secara langsung ke dalam bentuk biner, bilangan-bilangan tersebut direpresentasikan menggunakan format yang mencakup bit tanda (*sign bit*), eksponen, dan mantisa. Format ini dikenal sebagai standar IEEE 754.
Terdapat dua format utama:

  • Single precision (32-bit) for small numbers
  • Double precision (64-bit) for larger numbers

How does Floating-Point Representation Work?

The IEEE 754 standard defines how floating-point numbers are stored and calculated in computers. In single precision (32-bit), the format consists of:

  • 1 bit for the sign
  • 8 bits for the exponent
  • 23 bits for the mantissa
In double precision (64-bit), the format consists of:
  • 1 bit for the sign
  • 11 bits for the exponent
  • 52 bits for the mantissa

⋄Sign Bit
The sign bit indicates whether the number is positive or negative. If the number is positive, the sign bit is 0; if the number is negative, the sign bit is 1.
⋄Exponent Bits
The exponent represents the power of 2 by which the mantissa is multiplied. In single precision, the exponent is stored as an 8-bit biased integer, and in double precision, it is stored as an 11-bit biased integer. Just like the scientific notation, where a number can be represented using a mantissa and an exponent, the exponent in the floating-point representation serve the same purpose. The only difference being the base and a bias correction. This allows for a wide range of values to be represented. The bias is used to allow for both positive and negative exponents. This is because we can only have 8 bits to represent the exponent in single precision, which means we can only represent 256 different values (0 - 255). By using a bias of 127, we can represent exponents from -127 to +128.
⋄Mantissa Bits
The mantissa represents the precision bits of the number. It is stored as a binary fraction, with an implicit leading 1 for normalized numbers. Hence exponent is crucial, because it allows us to flexibly set the accuracy and the range of the floating-point.

Conversion (single-precision/32-bits)

  1. Set the sign bit based on wether the number is positive or negative.
  2. Convert both of the integer(Number in front of the comma) and the decimal points(number after the comma) into its respective binary representation. You can check here for a guide to do that.
  3. Normalise the binary representation, by moving numbers from the front of the comma to behind of the comma or vice versa. Do it until the number in front of the comma is only 1.
  4. The amount of the numbers you moved tells you the exponent. Note: if the numbers were moved from front to behind the comma, the exponent is positive. When the opposite is done, the exponent is negative. Just like in scientific notation.
  5. Normalise the exponent by adding 127 into it.
  6. Convert the normalised exponent into its binary representation. Here is a guide for it. This will become the exponent bits. Note: make sure it is on 8-bits format. If the converted exponent is not 8 bits long, simply add 0 in front of it until there is exactly 8 bits.
  7. Remember our normalised binary representation of the number on step 3? pick 23 bits of the mantissa(numbers behind of the comma) as our mantissa bits. If you somehow don't have 23 bits of it, i'm affraid you have to continue the conversion of the decimal-points on the step 2 until you have enough bits.
  8. Now put together all of the parts. The sign bit on the front, the exponent bits on the middle and the mantissa bit on the back.
  9. Congratulations, you have succesfully converted a number into its single-precision IEEE 754 binary floating-point representation
